# 达芬奇

剪辑这一步只用达芬奇做三件事：把画面和三条分轨摆上时间线，按规格出片，留一个工程方便以后换素材重出。混音在 `juzu stems` 里已经做完。

64 期用的是 DaVinci Resolve Studio 21.1。

## 工程长什么样

- V1：无声画面（`out/video_silent.mp4`，样片是 `out/sample_1080.mp4`）
- A1 人声，A2 配乐，A3 音效和环境声（`out/stems/{vo,music,fx}.wav`）
- 三条分轨和画面都从时间线开头（帧 86400，也就是 01:00:00:00）摆起
- 4K：3840×2160，24 帧，H.264，60000 kb/s，AAC 48 kHz
- 样片：1920×1080，24 帧，20000 kb/s

## 两种跑法

`juzu resolve_build` 做的事和下面两种跑法一样，核心是同一段代码。

**外部脚本。** 达芬奇开着，偏好设置 → 系统 → 常规 →「外部脚本使用」选「本地」，然后：

```bash
juzu resolve_build                # 只搭 4K 工程
juzu resolve_build --render       # 搭好就出片，等出完，量响度和偏移
juzu resolve_build --sample --render
```

脚本用达芬奇自带的 `DaVinciResolveScript` 模块。macOS 上它在 `/Library/Application Support/Blackmagic Design/DaVinci Resolve/Developer/Scripting/Modules`，找不到时设环境变量 `RESOLVE_SCRIPT_API`（指到 `Developer/Scripting`）和 `RESOLVE_SCRIPT_LIB`（指到 `fusionscript.so`）。免费版的达芬奇不支持外部脚本。

**MCP。** 装了达芬奇的 MCP 时：

```bash
juzu resolve_build --emit --render     # 打印一段脚本，也存到 out/resolve_build_mcp.py
```

把打印出来的第一段原样贴进 MCP 的 `run_script`，timeout 填 60。那边已经有 `resolve` 变量；沙盒里不能 import `os`、`sys`，所以核心代码只用达芬奇的 API。单次最多跑 60 秒，出片只负责开始；第二段是查进度的，隔一会儿贴一次，看到 `Complete` 为止。出完以后在终端跑 `juzu verify` 量响度和偏移。

## API 要点

```python
pm = resolve.GetProjectManager()
pm.SaveProject()                                  # 换工程（CreateProject / LoadProject）之前先存
proj = pm.CreateProject('名字')                    # 同名工程已经有了会返回 None，这时 LoadProject
proj.SetSetting('timelineResolutionWidth', '3840')
proj.SetSetting('timelineResolutionHeight', '2160')
proj.SetSetting('timelineFrameRate', '24')        # 分辨率和帧率都在建时间线之前设
mp = proj.GetMediaPool()
items = mp.ImportMedia([画面路径, 人声路径, 配乐路径, 音效路径])   # 只认路径字符串
tl = mp.CreateEmptyTimeline('成片_4K')
while tl.GetTrackCount('audio') < 3: tl.AddTrack('audio', 'stereo')
tl.SetTrackName('audio', 1, '人声')                # 2 配乐，3 音效和环境声
s = tl.GetStartFrame()                            # 86400
mp.AppendToTimeline([{'mediaPoolItem': 画面, 'mediaType': 1, 'trackIndex': 1, 'recordFrame': s},
                     {'mediaPoolItem': 人声, 'mediaType': 2, 'trackIndex': 1, 'recordFrame': s}, …])   # mediaType 1 画面，2 声音
proj.SetCurrentRenderFormatAndCodec('mp4', 'H264')
proj.SetRenderSettings({'SelectAllFrames': True, 'TargetDir': 出片目录, 'CustomName': 'final',
                        'AudioCodec': 'aac', 'AudioSampleRate': 48000, 'VideoQuality': 60000})
job = proj.AddRenderJob(); proj.StartRendering([job])
proj.GetRenderJobStatus(job)                      # {'JobStatus': 'Complete', 'CompletionPercentage': 100}
```

画面重渲以后不用重搭时间线：在媒体池里对那个素材 `clip.ReplaceClip(新文件)`，再出一次片。

## 坑

| 现象 | 原因 | 办法 |
|---|---|---|
| `ImportMedia` 返回 None | 传了字典 | 传路径字符串的列表 |
| `VideoQuality` 设不上 | 填了 `'Best'` | 填码率数字：1080 用 20000，4K 用 60000 左右 |
| 工程是 1080 或者 25 帧 | 建完时间线才改分辨率和帧率 | 建时间线之前设；工程里已经有别的帧率的时间线时改不了，换个工程名 |
| 成片比画面长出一截，尾巴是黑的 | 分轨比画面长（64 期长约 1 秒） | 出片范围设成画面的帧数：`'SelectAllFrames': False, 'MarkIn': 86400, 'MarkOut': 86400 + 帧数 - 1`。64 期是 20333 帧，MarkOut 106732 |
| 切工程以后改动没了 | 没存就 `LoadProject` | 换工程之前先 `SaveProject()` |
| 达芬奇出的片子比原片暗约 2 级（满级 255） | 渲染小块是全范围 yuvj420p、bt470bg 标签，达芬奇转成了 bt709 视频范围 | 肉眼看不出。渲染小块时直接编码成 bt709 视频范围（`-pix_fmt yuv420p -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709`） |

## 出完片要量的

`juzu verify`（`juzu resolve_build --render` 出完会自动量）：

- 分辨率、帧率、帧数和无声画面一致
- 响度 −16 LUFS 左右，真峰值不超过 −1 dB
- 和 `out/mix_ref.wav` 在三处做互相关，偏移 0 毫秒

64 期：847 秒的片子，达芬奇出 4K 用了 3 分 52 秒，60 Mb/s，约 6.4 GB；成片 −16.2 LUFS，真峰值 −1.2 dB，LRA 2.7，三处偏移都是 0。
