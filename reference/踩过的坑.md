# 踩过的坑

前面几期真踩过的。新踩的，收工时补在对应的表里。

## 稿子

| 现象 | 原因 | 办法 |
|---|---|---|
| 用户说稿子「一股 AI 味」 | 套话、对仗、书面连接词，句子切得整整齐齐 | 过 `flavor` 到 0 处，`score` 看哪几项在推分，按 `reference/文案.md` 改 |
| 改了一轮规则，分数反而更像 AI | 规则写得太硬，模型照着规则用力过猛 | 一次只改分数推得最多的两三项，改完再打分 |
| 片子里说的数字被追问出处 | 凭印象写的 | 数字只从运行记录和带日期的调研里取 |

## 配音

| 现象 | 原因 | 办法 |
|---|---|---|
| 听写准确率低，听起来却没错 | Whisper 把词听成了同音词 | 先听；配音没错就留着 |
| 片子里按语速算出来的数对不上了 | 稿子里「念完得五十三分钟」是按旧语速算的，后来改了 `voice.rate` 重配，语速变了 | 改语速以后把稿子、屏幕、简介里按语速算的数都重算一遍（67 期 53 → 51 分钟） |
| 配音有电音 | 成品做了时间拉伸 | 不拉伸；要快就用加快过的参考音 |
| 数字念得怪 | 配音文本里留了阿拉伯数字 | `vo/mk_lines.py` 的 `SAY` 里写好念法，`lines` 会拦住阿拉伯数字 |
| 作者听着配音太急、快慢不稳 | 开新一集抄上一集时 episode.json 漏了 `pause`，用了默认 0.72 / 0.18；稿子是只用逗号的长句，`inner` 用不上；每句只看听写准不准，语速 5.0 到 6.8 都有 | 抄 `pause`，加 `comma`；`voice` 写目标语速和范围，`tts --repick` / `--off`（66 期） |
| 成片出了才听出多音字念错（66 期「写个三五行」念成了 xíng） | 模型按最常见的读音念；Whisper 听写两种读音都写成同一个字，准确率照样是 1.0，查不出来 | `SAY` 里把这个词写成只有一个读音的同音字（`三五行` → `三五航`），字幕不变；`tts <键>` 重配这一句，`keep_slot <键>` 保住它在时间线上的位置，画面不用整片重渲。写稿时自己先过一遍多音字：行、长、重、还、得、地、着、了、好、数 |

## 作曲

| 现象 | 原因 | 办法 |
|---|---|---|
| 开场音乐「有点廉价」 | 用了 ACE-Step 的加速版（turbo，8 步） | 用 XL-SFT，50 步 |
| 铺底抢人声、节奏太强 | 有鼓点，拍子感重 | 提示词里不要鼓；用 `pulse` 量拍子感，挑低的 |
| 开场太响，总峰值超了 | 开场那段在 plan 里的增益给得太大 | 开场增益压低（前几期从 11 改到 4），限幅放在增益之后 |
| 机器初筛说「中间断了」，其实没断 | 结尾淡出之后又有一点小声音，前面那段静音没被算成结尾 | `screen_beds` 现在把最后一段连着 1 秒有声之后的都算淡出；还不放心就量一下静音在第几秒，落在这一段要用的长度以外就不碍事 |
| 去完哨音，有一段铺底还是比别的亮一大截 | 候选结尾冒出沙锤、镲片一类的声音（描述里写了 beatless 也会有）；初筛原来不看亮度 | `screen_beds` 加了「最亮dB」（−15 以上提醒）；不换候选就在这一段写 `eq` 压高架，65 期 crew_b 压 6 dB |
| 配乐高频刺耳 | ACE-Step 解码器在 2.5 到 18 kHz 留下几条一直不变的细线（哨音）；描述里 hall、spacious、celesta、music box 这类词和一串「no X」把亮、散的质感拉进来；母带链高频还提了一点 | `master_beds` 先过 `despur.py` 去哨音，母带链 8 kHz 减 2 dB、15 kHz 缓低通；`gen_beds` 用正面整句描述、guidance 5、固定种子、32 位浮点；一段别超过 240 秒，长的在 plan 里拆两截交叉淡化（`xf_in` / `xf_out`） |
| 调高增益的那一段在 bed.wav 里削顶 | `mix` 写的是 16 位整数 wav | 已改成 32 位浮点 |

## 素材

| 现象 | 原因 | 办法 |
|---|---|---|
| 下了一堆「免费」视频，最后不能用 | Mixkit 免费下载走 Restricted License：只能个人用，不能放进 YouTube 或任何能赚钱的视频 | 先读授权再下载；优先 Wikimedia Commons 上的公有领域、CC0、CC BY，不用 CC BY-SA（放进商业视频里说法不清） |
| Commons 标着公有领域的老电影，其实还在版权期 | 文件页上的年份是上传者写的，可能写错（Bobby Jones 教学片标 1927，其实是 1931 年华纳发行） | 去 TCM、AllMovie、IMDb 核一下发行年份；美国作品 1930 年及以前发表的才稳进公有领域，1931 年的要等 2027-01-01 |
| Commons 突然一直返回 429 | 连续搜得太快；之后 Python urllib 一直被限流 | 搜索之间隔几秒；下载用 curl（同一个 User-Agent 正常），一次 API 请求查多个文件 |
| 用脚本下载 Pexels 被拦 | 站点不让脚本下载 | 不绕，换 Commons |
| 照片里有能认出来的人 | CC0 只管版权，不管肖像 | 挑公共场所、不针对个人的照片；能用空镜就用空镜 |

## 片场

| 现象 | 原因 | 办法 |
|---|---|---|
| 联系表全是一样的百叶窗 | `render.mjs` 没加 `--page film.html`，渲的是默认页 | 加上 |
| 屏幕镜头太近，标题条被切 | dist 太小 | dist .84 时 u 不超过 .48 到 .52；u .5 时 dist 不小于 .88；整屏 dist .95 |
| 桌上的字被笔记本、手机压住 | 字块放得太靠左或太靠右 | 放在安全区里（x 1.12 到 1.97，z .665），手机挪开，镜头后拉 |
| 板子上的字和口播顺序对不上 | 导演表写乱了 | 导演表按口播顺序写 |
| 磨砂板上的字一直不出现 | 时间写法没经过 TX 转换，透明度成了 NaN | 叠字层里所有时间都过一遍 TX |
| 第一帧缺贴图 | 图还没加载完就渲了 | 新贴图放进 `extras.js` 的 `load()`，别同步加载 |
| 便签只显示一个字 | 不是 bug：便签是逐行写出来的 | 抽晚一点的帧看 |
| 彩蛋抢了桌上字的视线 | 颜色太亮（米白鼠标垫） | 彩蛋用暗、安静的颜色 |
| 4K 渲到一半「显卡上下文丢了」 | 分块按 1080 定的，4K 每块太大 | 4K 时分块数乘 4 |
| 夜里渲染时电脑睡了 | 闲置休眠 | `caffeinate -i -w <进程号>` |
| 终端录屏露出用户名 | 临时路径里带着家目录 | 录之前把路径换成 `~`；抽帧时专门查一遍 |
| 悬浮段第一版被打回来：「没来由」 | 在空中凭空打开一扇传送门、画一圈符文，照片从门里飞出来；观众第一反应是「这是哪来的」 | 东西要有一个说得通的来处：要么本来就在屋里（墙上的照片被揭下来），要么当着观众一点点长出来（手心上方的光点飘到位置，金线描出方块，再显出纸面）。现在的 `magic.js` 就是这样 |
| 白天、下午的光里书桌那一侧发灰发暗 | `day`、`afternoon` 太阳高，直射光只落在窗下的地板上，书桌和背墙照不到 | 书桌的戏用 `lowsun` 或 `night`；`day`、`afternoon` 只给床角那边用，换之前先抽一帧看 |
| 小机器人近景里，显示器的大标题被画面上沿切掉一半，糊在章节进度条上 | 近景里显示器只露出一部分，标题正好在画框上沿 | 导演表写 `CALM: ['talk']`，这些机位里显示器只留安静的底色；重点放在磨砂卡和贴图上 |
| 素材里自带的字幕和我们的字幕叠在一起 | MV、带字幕的片段下方本来就烧着歌词或字幕 | 抽帧时把下方字幕条裁掉，比如 `ffmpeg -i 素材.mp4 -vf "fps=24,crop=iw:ih*.84:0:0" f%04d.jpg`，裁完抽几帧确认 |
| 床角全景里椅背挡着床尾 | 椅子摆在书桌和床之间，从上往下看椅背压着床尾那个角 | 椅子挪到 (1.55, .98)，`bedwide` 机位跟着挪；挪家具以后用 `?pose=` 摆一个俯视机位看一眼有没有东西相碰 |
| 飞的东西拖出一层层的重影 | 运动模糊是一个个采样叠出来的，16 个采样时飞得快的东西每层隔得太开 | 快的那几秒用 32 个采样：悬浮段出片时自动升，别处在导演表写 `NS`；细亮的线在飞的时候压暗 |
| 有的镜头接过去「跳一下然后变暗」 | 4K 按 3 秒一块分开渲，每块开头重新拍一次环境反射；屏幕内容、悬浮的光、全息、手机这些会动会亮的东西被拍进去了，每块拍到的不一样 | 拍环境反射前把会动的东西藏起来（`stage.envHide`），屏幕换成固定的暗灰，百叶和床头灯按「上一刀」的状态摆好；灯光正在过渡时每帧重拍。改完用同一时刻分块渲和连续渲比一下亮度 |
| 推进的时候卡一下，虚实来回 | 机位之间默认往后让一点，推进里夹了一下后退；对焦点按三维点插值，对焦距离先变远再变近 | 只有导演表写了 `arc` 才让；对焦按「离镜头多远」在对数上单调地走，比镜头先到 |
| 磨砂卡有的比字大一圈，有的字跑出框 | 卡的宽高是手写的，字一改就对不上 | `overlay.js` 按字量框（`fitBox`）；靠下的卡写 `anchor: 'bottom'`，底边不动 |
| 东西「莫名其妙从桌子里长出来」 | 没有来处 | 用屋里本来就有的东西：比如桌上的笔记本，小机器人飞过去把它打开 |
| 切得太勤，有的镜头一两秒就切走 | 镜头跟着每句旁白切 | 短于 3.5 秒的镜头合并或延长；同一个屏幕镜头里换内容不用再切；一个个点名物件的地方改成连续横摇。导演表写完用 `camlist` 一类的脚本数一遍每个镜头多长 |
| 浮空板上的清单只占左边三分之一 | 清单从左边距画起 | `screen.js` 的清单写 `center: 1`，字放大（`big`、`subSize`） |
| 导演表时间写 `d26$+1.0-3.4` 报 KeyError | 时间写法只认一个偏移 | 换算成一个：`d26$-2.4` |
| 导演表里 `'c05:关键词'` 找不到 | 分句文本是 `lines` 换过的念法（「GTA 六」「H U D」「十一月十九号」），不是稿子原文 | 关键词照 `vo/lines.py` 里的念法写；关键词要落在同一个分句里 |
| 想要游戏画风的屏幕 | 原来的屏幕画法都是扁平的信息图 | 66 期的 `set/screen_game.js`：800 宽的小画布画像素，再最近邻放大；地图、HUD、存档、NPC 对话、读条、迷雾、集章卡等 18 种，导演表里直接写 `kind: 'gtitle'` 这类 |
| 作者看样片：运镜一顿一顿、推过去又跳回来 | 同一个机位连着切、短镜头来回切、全是硬切 | `smooth.js`（导演表写完调一次）；`tools/campath.mjs` 量（66 期） |
| 顺滑处理把换光那一刀改成了滑 | 光是瞬间换的，滑的开头光一下子变 | `smooth(…, { cuts: LIGHT 的时刻 })` 保持硬切（66 期 c01） |
| 整屏镜头里屏幕最底下一行压在字幕上 | 整屏 dist .95 时屏幕底边落在 1012 到 1070 像素，字幕基线 1008 | 整屏写 `full: 1`，smooth 统一 v .563、dist ≥ 1.02（66 期） |

## 声音和出片

| 现象 | 原因 | 办法 |
|---|---|---|
| 用户嫌音效刺耳 | 起音太快，高频太多 | 按 `scripts/sound/` 的柔化规则做，新音效先单独试听 |
| 环境声开头空了 1 秒 | 预卷把第一段提前了 | 第一段不预卷 |
| 音效库截到安静处，放大后全是底噪 | 随便截一段 | 挑最响的几段 |
| 达芬奇导入返回 None | 传了字典 | 传路径字符串 |
| 达芬奇 `VideoQuality` 填 'Best' 失败 | 要填码率数字 | 1080 用 20000，4K 用 60000 左右 |
| 达芬奇出的片子比原片暗一点 | 渲染小块是全范围，达芬奇转成了 bt709 视频范围 | 小块直接编码成 bt709 视频范围 |
| ffmpeg 报 `-vsync` 不支持 | 新版改名了 | 用 `-fps_mode passthrough` |
| 发到手机的样片打不开 | 超过 30 MB | 另压一份 720p，两遍编码约 1.15 Mb/s |
| 有几下敲桌声比别处响 | 箭头和后面的字块同一刻落下，两声叠在一起 | `set_fx` 把 60 毫秒以内的同种动作并成一声；出片前拿上一期过了的分轨对一下，音效比人声低多少（64、65 期中位数都在 6 dB 左右） |
| 新加的动作（手机翻面、全息、笔记本、小机器人飞走飞回）没有声音 | `events` 只认几种老动作，别的只能手写进 `set_fx.extra` | `events.mjs` 现在从导演表里直接推出这些声；手写的 `extra` 留空 |
| 人声一停配乐就往上冒 | 闪避的释放时间 400 毫秒太快 | `stems.py` 改成 900 毫秒 |
| 屋里太「真空」 | 只有配乐和音效 | 加一层窗外环境声：隔着玻璃（低通 3 kHz 左右），比配乐低 12 LU，白天、夜里跟灯光同一刀换；录音挑中频没有突出东西的段落，接成长循环 |
| mp3 做环境声读不进来 | soundfile 不一定读 mp3 | 先转成 wav |
| 达芬奇出的 4K 成片不能直接上传 B 站 | `VideoQuality` 60000 出来平均就是 60 Mbps，最高的一秒到 97（67 期），超过社区整理的 4K 峰值上限 60 Mbps | 另压一版：x264 `-crf 16 -maxrate 45M -bufsize 15M`，声音 `-c:a copy`，`+faststart`，标好 bt709；`publish --video out/final_upload.mp4`，不加 `--video` 发布包里放的是 final.mp4（67、68 期） |

## 宣发

| 现象 | 原因 | 办法 |
|---|---|---|
| 用户说封面和上一期「完全一样」 | 版式和图形都照搬 | 版式可以沿用，图形每期换一个和这期内容有关的点子 |
| 「我是怎么做的」这类标题没人点 | 标题里没有证据，陌生人不知道值不值得点 | 标题里放一个真实、具体的数字或结果 |
