# 6 剪辑出片

这一步把声音拼好、分成三条，和画面一起放进达芬奇出片。先出前三分钟的 1080 样片给用户看，点头以后再出 4K 整片。

## 声音备齐

前面几步做完，这一集里应该有：

| 文件 | 从哪来 |
|---|---|
| `out/vo.wav` | 配音（`juzu timeline`） |
| `music/<段名>.wav` | 作曲（`juzu master_beds`） |
| `out/sfx_cues.wav` | 柔和音效（`juzu cue_fx`） |
| `out/sfx_set.wav` | 片场动作声（`juzu set_fx`） |
| `music/amb/<名字>.wav` | 环境声（`juzu ambience`），`cues.json` 的 ambience 里写了才有 |

```bash
juzu mix      # 按 plan 拼配乐 → out/bed.wav
juzu stems    # 三条分轨 → out/stems/{vo,music,fx}.wav，和混音参考 out/mix_ref.wav
```

`stems` 会打印三条相加的响度和真峰值，目标是 −16 LUFS、不超过 −1 dB。它自己会调总增益和人声的限幅线，一般跑一次就到。压到 −5 还超，就是配乐某段太响：改 `cues.json` 再跑。各项数字为什么这么定，见 `reference/混音.md`。

## 样片：前三分钟，1080

画面用片场渲染出来的前三分钟（第 4 步，`out/sample_1080.mp4`，开场蒙太奇已经盖上）。分轨用整片的就行，出片范围会自动卡在画面的长度。

```bash
juzu resolve_build --sample --render
```

出完会自动量响度、和混音参考比偏移。没有外部脚本（免费版达芬奇），用 `--emit` 走 MCP，见 `reference/达芬奇.md`。

再压一份给手机看的，要小于 30 MB：64 期发到手机上的样片超过了 30 MB，打不开。720p、两遍编码、视频 1.15 Mb/s，三分钟约 29 MB：

```bash
ffmpeg -y -i out/样片_1080.mp4 -vf scale=1280:720 -c:v libx264 -b:v 1150k -pass 1 -an -f null /dev/null
ffmpeg -y -i out/样片_1080.mp4 -vf scale=1280:720 -c:v libx264 -b:v 1150k -pass 2 -c:a aac -b:a 128k -movflags +faststart out/样片_手机看.mp4
```

## 停点：给用户看样片

给用户：样片（1080 和手机版）、三条相加的响度和真峰值、这三分钟里有哪些音效和环境声。画面、节奏、混音的大方向在这里定。作者说「后面全部做好给我」的话，后面一路做到 4K 成片，不用再停。

改了声音只要重跑 `stems` 和达芬奇出片，几分钟；改了画面才要重渲。

## 4K 整片

画面：片场渲染整片 4K（第 4 步），拼成 `out/video_silent.mp4`，3840×2160、24 帧。渲染要一个多小时，别和配音、作曲同时跑；夜里跑记得防止电脑睡着（`caffeinate -i -w <进程号>`）。

```bash
juzu stems                       # 声音改过就重出
juzu resolve_build --render      # 搭 4K 工程并出片 → out/final.mp4
juzu verify --sheet              # 再量一遍，出 24 格联系表 out/check_sheet.jpg
```

`verify` 查：分辨率、帧率、帧数和无声画面一致；−16 LUFS 左右、真峰值不超过 −1 dB；和 `out/mix_ref.wav` 在片子的 1/4、1/2、3/4 三处做互相关，偏移 0 毫秒。联系表要自己看一眼：有没有黑帧、有没有露出电脑用户名的终端画面。

64 期：847 秒的片子，4K 整片渲染约 75 分钟（三路），达芬奇出片 3 分 52 秒，60 Mb/s，约 6.4 GB；−16.2 LUFS，真峰值 −1.2 dB，三处偏移都是 0。

只交 4K 这一个文件，1080 和 720 都不要。

## 记进运行记录

`stems`、`resolve_build`、`verify` 会自己往运行记录里写一笔：响度、峰值、增益、出片范围、用时。画面渲染的用时和每帧毫秒数自己补上。
