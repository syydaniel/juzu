# 3 作曲

作曲用本机的 ACE-Step 1.5。要写两种音乐：开场一段，配开场画面，可以有一点电影感；口播底下几段铺底，一段垫一到两章。

作者对配乐只有一个要求：平缓、优美，节奏感弱，不要鼓点。64 期第二版铺底有鼓、有拍子，作者看完成片说「节奏感太强、不太好」，整套重写了一遍。

## 先写 cues.json 的 beds

每段一个名字，写调、速度、长度、种子和英文描述（写法见 `template/cues.json`）。几条经验：

- **一段按它要垫的长度一次写完，不循环。** `dur` 写 `"auto"`，脚本按 plan 里这段要用的最长一截算，多留 8 秒。循环接出来的音乐听得出原地打转。
- **歌词栏写段落标签。** `[Intro]`、`[Verse]`、`[Bridge]`、`[Outro]`，每个标签下面一句乐器提示，比如 `[soft string pad joins]`。长段这样才有变化。
- **描述里写乐器和情绪，别写节奏。** 钢琴、弦乐长音、远处的钢片琴这类最稳。脚本会在每段描述后面自动加一句「真乐器、安静的厅、没有鼓、没有拍子、给旁白让路」（`calm`，默认开）。
- **各段的调最好有共同的音。** 柔和音效会挑这些音，免得和铺底打架。64 期是 F 大调、A 小调、C 大调、降 E 大调，共有 C、D、F、G。
- 开场那段写 `"role": "open"`。

## 写候选

```bash
juzu gen_beds                 # 全写；也可以只写一段：juzu gen_beds explain，或者一个：juzu gen_beds explain_4102
```

- 模型是 XL-SFT（4B），50 步，加 4B 规划模型。turbo（8 步）快很多，但作者听出来「劣质」：64 期开场第一版就是 turbo 写的，换成 XL-SFT 才过。
- 很吃显卡，写的时候别渲染、别配音。64 期的用时：36 秒的开场 74 秒，220 秒的铺底约 13 分钟，420 秒的约 30 分钟。
- ACE-Step 自带 600 秒的生成超时，写长段会撞上，进程跟着崩掉。脚本默认放宽到 3600 秒。
- 每段写两三个种子。开场多写几个，它最显眼。

## 机器初筛

```bash
juzu pulse          # 只量拍子感
juzu screen_beds    # 拍子感加闷不闷、抢不抢人声、有没有沙沙声、中间断没断
```

拍子感是起音强度包络在 0.3 到 1.5 秒间隔上的自相关，0 到 1，越低越平缓。64 期的数（运行记录 11-17）：

| 段 | 第二版（有鼓） | 第三版（作者认可） |
|---|---|---|
| explain | 0.85 | 0.31 |
| toy | 0.65 | 0.21 |
| now | 0.73 | 0.23 |
| close | 0.28 | 0.44（没用，留了第二版） |

`screen_beds` 的提醒线是拿 64 期的候选对出来的：拍子感 0.4 以上、人声带（1 到 4 kHz 的能量占比）30% 以上、高频毛刺 0.8 以上、中途掉到 −50 dB 以下超过 4 秒。淘汰的候选都会被提醒，选中的都不会。突变次数和循环感只在同一段的候选之间比：安静、有呼吸的铺底这两个数天然偏大。

机器只做初筛。数好看的也可能难听。

## 停点：给用户听

每段挑 2 到 3 个机器没提醒的候选，连同拍子感、人声带的数一起给用户。开场配一下画面再给，单听音乐判断不了。作者定了，把候选名写进 `cues.json` 的 `pick`。

## 母带和拼接

```bash
juzu master_beds    # 按 pick 做成 music/<名字>.wav：铺底 −20 LUFS；开场原样转 48 kHz，不压
juzu mix            # 按 plan 拼成 out/bed.wav
```

旧的 `music/<名字>.wav` 会挪到 `music/old/` 留着对照。plan 里开场那段的 gain 别给太大，64 期给到 11，总峰值超了，改成 4。

## 注意

- 作者说「音质一定要好」，那就宁可多等，也别为了快退回 turbo。
- 换铺底以后，前后对比给用户听：同一段画面，新旧两版归一到同样响度，剪成一条。
- 记进运行记录：每个候选的种子、长度、用时、拍子感，选了谁、为什么。
