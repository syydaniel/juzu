# 7 宣发

宣发把成片之外要交的东西备齐：封面、标题、简介、置顶评论、字幕，再做一遍发布前的体检，列出只有耳朵能判断的地方。做完交给用户。上传、发布、回评论都是用户自己的事。

## 先准备

- **封面**：放在 `cover/`，三个尺寸：16:9 的 3840×2160、4:3 的 1440×1080、3:4 的 1080×1440。脚本按图片的实际尺寸挑，文件名随意。
- **发布文案.md**：放在这一集的目录里。要有这几块：标题（三选一）、封面说明、简介（带章节时间）、标签、置顶评论、常见问题的回复、其他平台的说法。没有的话 `publish` 会生成一份空架子，章节时间已经按时间线填好，其余写「待填」。
- 简介和标题里的每个数字都要能在运行记录里找到。片子里用了 AI 合成的旁白、生成的配乐、现成的录音，在说明里写清楚；各平台发布页都要勾选 AI 生成内容的声明。

## 出发布包

```bash
juzu publish                 # → 这一集的 发布包/
juzu publish ~/某处/发布包/09_片名      # 指定目录
```

发布包里：

| 文件 | 说明 |
|---|---|
| `成片_4K_3840x2160.mp4` | `out/final.mp4`。同一个磁盘上用硬链接，不多占地方 |
| `封面_横版_16比9_3840x2160.jpg` 等三张 | 从 `cover/` 按尺寸挑 |
| `发布文案.md` | 拷过来，或者空架子 |
| `字幕.srt` | `out/字幕.srt`，没有就按时间线现做 |
| `口播稿.md` | 按章节排好的定稿 |
| `运行记录.md` | 拷过来 |
| `请戴耳机检查.md` | 机器查过什么，以及要人听的时刻 |
| `体检.json` | 体检的全部结果和问题 |

## 体检查什么

机器能查的都查，不做 OCR：

- **成片**：分辨率、帧率、时长、响度、真峰值、和混音参考的偏移、24 格联系表（同 `juzu verify`）。
- **禁用字**：`config.json` 里 `banned_words` 的字词。在发布包的所有文字、`vo/草稿.txt`、时间线里的字幕、片场 `set/` 下的脚本和数据、`cover/` 的封面工程里找。
- **身份**：本机的家目录路径、电脑用户名，以及 `config.json` 里 `private_words` 写的真名、账号名。在同样这些文件里找。终端录屏的数据在 `set/` 里，最容易漏：64 期抽帧时抓到过两处露出用户名的临时路径，是渲染完才发现的。
- **发布文案**：有没有标题、简介、置顶评论，还有没有「待填」。

有问题会列出来，命令以非 0 退出。改完再跑一次，直到没有问题。

## 请戴耳机检查

脚本按时间排好只有耳朵能判断的时刻，用户大约十分钟能听完：

- 环境声每一段：垫在音乐底下合不合适，切画面时跟着换会不会突兀。
- 片场动作声最密的 10 秒：会不会太碎、太密。第一次纸展开、第一次小机器人跳进屏幕：音色合不合适。
- 小铃、片尾的低音落在哪个词上。
- 人声在说话、配乐又相对最响的三处（按 3 秒一块，算配乐比人声低多少 dB，差得最少的三块）。64 期结尾那段铺底慢慢推高，这里能抓出来。
- 铺底换段和章节气声的时刻。
- 配音里听写准确率低的句子（看运行记录里配音那一条）。

脚本列不出来的，自己补进去：比如某句改过配音、某个音效是新加的。

## 停点：交给用户

给用户：发布包的路径、体检结果（响度、真峰值、偏移、问题个数）、`请戴耳机检查.md`。不替用户上传、发布、回复评论；推 GitHub 这类公开动作先问。

用户听完说哪一声不舒服，改 `cues.json` 或音效，重跑 `stems` 和达芬奇出片，再跑一次 `publish`。不用重渲画面。

用户听出哪句念错了字：见 `stages/2-配音.md` 的「出片以后改一句」，用 `keep_slot` 保住这一句的位置，画面最多补渲几块。
